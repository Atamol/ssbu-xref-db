# ssbu-xref-db

Static analysis database for SSBU.

It stores xrefs, function info, decompiled code and more pulled out of Ghidra as files other tools and projects can reuse.
Functions that projects listed in `CONSUMER_SOURCES` use by mangled name get the project name in their `Function Referenced By` column.

Target: Ver.13.0.5 main (loaded into Ghidra as an NSO, image base 0x7100000000).

## Layout

```

├── RUNTIME_FLOW.md               on-device testing steps with call-sniffer

│   ├── memory-search_<name>.csv  per-search CSV (generated by split.py)

│   ├── ingest_call_log.py        turn call-sniffer logs into runtime xrefs

├── xrefs/                        per-search xref list

├── reports/                      human-readable reports
```

Related repos:

- [ssbu-socket-sniffer](https://github.com/Atamol/ssbu-socket-sniffer): socket sniffer / anti-cheat mod
- [ssbu-call-sniffer](https://github.com/Atamol/ssbu-call-sniffer): dynamic analysis mod. `scripts/generate_hooks.py` builds its hooks from this DB, and `scripts/ingest_call_log.py` turns its logs into `tables/runtime_xrefs.csv`, which shows indirect calls Ghidra missed.
- [ssbu-decomp](https://github.com/sbergeron42/ssbu-decomp), [SSBU-Dump-Scripts](https://github.com/rubendal/SSBU-Dump-Scripts): sources for function names and hash40 labels

## Addresses

- Locations in `searches/` are absolute 13.0.5 addresses (`71xxxxxxxx`), so Ghidra's Memory Search table can be pasted as is.
- `Function Offset` and the other `*_offset` columns are image offsets (address - 0x7100000000) and can be used as is in `skyline::hook(offset = ...)`.
- NSO file offsets are image offset + 0x100. The DB loaded raw with Binary Loader (13.0.4 and before) uses them, and so do the .text `OFF_*` constants in socket-sniffer that are used with `- 0x100`, while its BSS `OFF_*` constants and `OFF_UPDATE_TAG` are already image offsets.
- Translate 13.0.4 offsets to 13.0.5 with `py scripts/remap_version.py map <off>` (`unmap` goes the other way).

## Usage

### Updating search results

1. Run a memory search in Ghidra.
2. Append the results to `searches/memory-search_all.md` (as a code block under `- <name>:`).
3. Add new terms to `CATEGORY_ORDER` in `split.py` (otherwise they land in `Other`), then regenerate the CSVs with `py searches/split.py`.

### Running the analysis

1. Open `main_decompressed_v13.0.5` in Ghidra.
2. Add `scripts/` via Script Manager > Manage Script Directories.
3. Run `DumpXrefs.java` from the `SSBU` category.

When it finishes, INDEX.md is updated and tables, reports and decompiled files are written. Args (`key=value`) are all optional.

- `root=<dir>`: input and output root, defaults to the parent of `scripts/` (this repo)
- `deps=<dir>`: base for the relative dependency paths, defaults to `root`
- `only=<a,b>`: searches to process
- `tables=<a,b|all|none>`: tables to write
- `decomp=false`: skip decompiling
- `clean=false`: overwrite without deleting old generated files first
- `game_version=<str>`: version recorded in meta.csv and INDEX.md

With `clean=true` (default) the run first deletes only the generated files it rewrites, so outputs of categories outside `only=`, tables outside `tables=`, passes turned off with `INCLUDE_*` and hand-kept files stay.

A run with `only=` still rewrites `funcs/funcs_all.csv`, `reports/report_all.md`, `reports/coverage.md`, `rust-externs/all.rs` and INDEX.md from the selected categories alone, and the `clones`, `constants` and `hash40_loads` tables too unless they're left out of `tables=`, so do a full run before committing.

### What output to use when

- DB overview: `INDEX.md`
- functions to hook: `reports/report_all.md`
- unreferenced hook candidates: filter `funcs/funcs_all.csv` by empty `Function Referenced By`
- copy-paste hook skeletons: `rust-externs/<category>.rs` (written only when a reached function has a mangled name, and none does in the current DB)
- mangled names: `Function Symbol` column of `funcs/funcs_all.csv`
- function body: `decompiled/<name>__<addr>.c`
- control flow: `decompiled/<name>__<addr>.mmd` (renders directly on GitHub)
- functions across multiple categories: `Categories` column of `funcs/funcs_all.csv`
- class hierarchy: `tables/typeinfo.csv` + `tables/vtables.csv`
- struct layout (e.g. what `*(uint*)(this+0x28)` is): `tables/structs.csv`
- enum value reverse lookup: `tables/enums.csv`
- where a constant is used: `tables/constants.csv` (e.g. PRUDP packet ID, NEX error code)
- whether some string is referenced: `tables/strings.csv` or `tables/string_xrefs.csv`
- all functions referencing a string: filter `tables/string_xrefs.csv` by `String Value`
- impl function for a hash40 identifier: filter `tables/hash40_loads.csv` by label name (e.g. `sleep_parallel_matching`). Loads from code outside any function leave the function columns empty.
- memory block / section layout: `tables/segments.csv`
- symbols imported from external modules: `tables/imports.csv`
- per-namespace size: `tables/namespaces.csv`
- grep all symbols: `tables/symbols.csv`
- which function an address belongs to: `tables/functions.csv`. `Ranges` holds Ghidra's function body as `lo-hi` image offsets (hi inclusive, `;` between ranges), so an address outside every range is code Ghidra has no function for. `Name` has the same form as the `Callers` column. `generate_hooks.py` and call-sniffer's `decode_log.py` use the table when it exists, and `ingest_call_log.py` uses it only when `tables/call_sites.csv` exists too.
- whether Ghidra knows a call: `tables/call_sites.csv`, one row per call reference from an instruction (`Site`) to a function entry (`Target`). `Thunked` is the function a thunk finally reaches. Calls through a thunk have the thunk in `Target`, so filter by `Target` or `Thunked` to get every call site that reaches a function. `ingest_call_log.py` looks up the instruction before each logged return address here to tell a call Ghidra has (`direct`) from one it missed.
- duplicate impl detection: `Clone Hash` column of `tables/clones.csv`
- call paths: `chains/chains_<name>.csv`
- per-category function relations: `reports/callgraph_<name>.mmd`
- analysis progress: `reports/coverage.md`
- byte sequence for sig-scan after a version update: `Function Fingerprint` column (first 32 bytes)
- error codes / magic numbers: `Constants` column
- globals a function touches: `Globals Accessed` column
- existing Ghidra annotations (Pre/Post/EOL/Plate/Repeatable): `Comments` column
- decompile failure fallback: `decompiled/<name>__<addr>.asm`
- name candidates for unnamed `FUN_xxx`: `Suggested Name` and `External Names` columns (curated first, then ssbu-decomp)
- judging function importance: combine `Function Size`, `Function Basic Blocks`, `Function Incoming Refs`
- which program and binary the DB was built from: `tables/meta.csv`

### Project linking

Add the source paths of other projects to `CONSUMER_SOURCES` in `scripts/DumpXrefs.java`. The script detects the mangled names (`_Z...`) used in those source trees and puts the project name in the `Function Referenced By` column. Import thunks are matched by their original mangled name.

```java
static final List<String> CONSUMER_SOURCES = List.of(
    "../../system/ssbu-socket-sniffer/src",
    "../some-other-mod/src");
```

### Following a game update

1. Diff the old and new main instruction by instruction and write the result to `tables/version_map_<old>_<new>.csv` (columns `old_start,old_end,delta,confidence,region`). The repo has no tool for this step.
2. Point `VERSION_MAP_CSV` in `DumpXrefs.java` at a map from 13.0.4 to the new version. ssbu-decomp names are tied to 13.0.4 offsets, so compose it with the earlier maps when the old version isn't 13.0.4.
3. Translate the `searches/` Locations and the offsets in the hand-kept tables under `tables/`, and drop rows that no longer match on the new version. `scripts/remap_version.py --map tables/version_map_<old>_<new>.csv map <off>...` (or its `VersionMap` class) only maps the offsets given to it and doesn't rewrite files, so write the Locations back into `searches/memory-search_all.md` as the mapped offset + 0x7100000000 and re-run `split.py` (it rewrites `memory-search_*.csv` from the md).
4. Run `DumpXrefs.java` on the new version in Ghidra with `game_version=<new>`.

## Main settings

These constants at the top of `scripts/DumpXrefs.java` change how it runs.

- `MAX_DEPTH`: xref hop count
- `INCLUDE_DECOMP` / `DECOMP_TIMEOUT`: decompile or not, and the timeout in seconds
- `INCLUDE_CHAINS` / `CHAIN_DEPTH` / `CHAIN_FANOUT`
- `INCLUDE_CFG` / `INCLUDE_STRUCT_ACCESS` / `INCLUDE_CLONES` / `INCLUDE_VTABLES`
- `INCLUDE_FINGERPRINT` / `INCLUDE_CONSTANTS` / `INCLUDE_TYPEINFO`
- `INCLUDE_RUST_EXTERNS` / `RUST_EXTERNS_TOP_N`
- `INCLUDE_CALLGRAPH` / `CALLGRAPH_TOP_N`
- `INCLUDE_SYMBOL_CATALOG` / `INCLUDE_FUNCTION_CATALOG` / `INCLUDE_CALL_SITES` / `INCLUDE_STRING_CATALOG`
- `INCLUDE_CONSTANTS_INDEX` / `CONSTANTS_INDEX_MIN_USERS`
- `INCLUDE_NAMESPACE_TREE` / `INCLUDE_INDEX_MD` / `INCLUDE_META`
- `INCLUDE_STRUCTS_CATALOG` / `INCLUDE_ENUMS_CATALOG`
- `INCLUDE_STRING_XREFS` / `INCLUDE_SEGMENTS` / `INCLUDE_IMPORTS`
- `INCLUDE_DISASM` / `INCLUDE_COMMENTS` / `INCLUDE_GLOBALS_ACCESS`
- `INCLUDE_NAME_HINTS`
- `INCLUDE_BRUTE_REFS`: scan data blocks for pointers Ghidra missed
- `INCLUDE_STRING_TABLES`: detect tables of string pointers
- `INCLUDE_HASH40` / `INCLUDE_HASH40_FULL_SCAN`: detect MOVZ/MOVK hash40 loads (FULL_SCAN walks every instruction, code outside functions included)
- `HASH40_LOADS_PER_FUNC`: cap on the `Hash40 Loads` cell (`tables/hash40_loads.csv` keeps every load)
- `HASH40_LABELS_CSV`: path to ParamLabels.csv (default `../SSBU-Dump-Scripts/ParamLabels.csv`)
- `VERSION_MAP_CSV`: offset map used to translate ssbu-decomp names
- `EXTERNAL_NAME_SOURCES`: external name DBs in priority order, `tables/curated_names.csv` then [sbergeron42/ssbu-decomp](https://github.com/sbergeron42/ssbu-decomp)
- `INCLUDE_EXTERNAL_FUZZY` / `EXTERNAL_FUZZY_TOLERANCE`: size-matched fuzzy lookup (off by default)
- `CONSUMER_SOURCES`: source paths of other projects to scan
- `NRO_BASE_OVERRIDE`: module base (null uses Ghidra's image base)
